## 【テーマ1】社内イベント管理システム

社員同士の交流を深めるために、社内イベントやサークル活動の告知・参加申込みができる社内向けのWebシステムを作成したい。

### 1. 実現したいこと（概略要件）

* **イベントの作成と公開**
  * 企画者（社員）が、イベントの概要（日時、場所、定員、内容）を投稿できるようにしたい。
* **イベントの閲覧と参加申し込み**
  * 他の社員が、一覧からイベントを探して「参加申し込み」ボタンを押せるようにしたい。
  * 定員に達したら自動で受付終了にしてほしい。
* **Myページ（参加予定の確認）**
  * 自分が「参加予定のイベント」や「過去に参加したイベント」を一覧で確認できるようにしたい。
* **通知機能（できれば）**
  * イベント前日になったら、参加者にリマインドメールが届くと嬉しい。

### 2. 利用規模・環境など

* **対象ユーザー数:** 約300名（社員）
* **アクセス環境:** 社内ネットワークからのみアクセス可能

### 3. 基本設計での検討事項・タスク

* [ ] **画面一覧・画面遷移のイメージ**
  * 必要な画面の洗い出し（例：ログイン画面、イベント一覧画面、イベント詳細画面、イベント作成画面、マイページ など）
* [ ] **データ（テーブル）の定義**
  * システムで保持すべきデータの整理（例：社員テーブル、イベントテーブル、参加申込テーブル など）
* [ ] **仕様に関するヒアリング（疑問点の洗い出し・確認）**
  * キャンセル機能やキャンセル待ち機能の有無
  * イベントの編集・削除の権限と仕様
  * 定員到達時の表示・挙動の詳細

## 【テーマ2】社内備品・PC資産貸出管理システム

社員が業務で使う検証用端末やプロジェクターなどの備品を、オンラインで予約・貸出・返却管理できるWebシステムを作成したい。

### 1. 実現したいこと（概略要件）

* **備品の閲覧・在庫状況確認**
  * 社員が利用可能な備品の一覧を検索し、現在の貸出状況（貸出可能／貸出中／メンテナンス中など）を確認したい。
* **備品の予約・貸出申請**
  * 利用したい期間（開始日時〜終了日時）を指定して予約を入れたい。
  * 重複予約（同じ備品が同じ時間帯に二重予約されること）を防ぎたい。
* **返却管理と返却期限アラート**
  * 備品を返却した際、状態（異常なし／破損あり等）を記録して返却完了としたい。
  * 返却期限を過ぎている社員や、返却予定日当日の社員へ督促通知を送出したい。
* **管理者機能（備品マスタ・在庫管理）**
  * 総務担当者が新しい備品を登録したり、故障した備品を一時的に利用不可にステータス変更できるようにしたい。

### 2. 利用規模・環境など

* **対象ユーザー数:** 約200名（全社・一般社員 ＋ 管理者）
* **扱う備品数:** 約500点（PC、タブレット、モニター、モバイルWi-Fi等）
* **アクセス環境:** 社内Webブラウザ（PC・スマートフォン両対応）

### 3. このテーマで学べる設計のポイント

* **期間（時間軸）を持った排他制御・重複チェック**のデータ設計
* **ステータス遷移（予約中 → 貸出中 → 返却済 / 遅延中）**の状態管理設計
* **管理者権限と一般ユーザー権限**による画面・APIのアクセス制御分離

### 4. 基本設計での検討事項・タスク

* [ ] **画面一覧・画面遷移のイメージ**
  * 備品一覧・検索、予約申請、自身の貸出一覧、管理者用備品登録・返却確認画面など
* [ ] **データ（テーブル）の定義**
  * 備品マスタ、資産管理番号、貸出/予約トランザクション、ユーザーマスタなど
* [ ] **仕様に関するヒアリング（疑問点の洗い出し・確認）**
  * 延長申請の可否、返却遅延時のペナルティや管理者通知の仕様、破損時の運用フローなど

## 【テーマ3】複数人対応・旅行の旅程（しおり）作成＆思い出管理ツール

友達や家族との旅行前に「旅程（タイムスケジュール）」を共同作成・共有し、旅行中〜旅行後には写真や支出・立ち寄りスポットのログを残せるWebシステムを作成したい。

### 1. 実現したいこと（概略要件）

* **旅程（しおり）の作成・タイムスケジュール管理**
  * 旅行のタイトル、日程（◯月◯日〜◯月◯日）、参加メンバーを設定し、日ごとのタイムスケジュール（移動手段、訪問スポット、滞在予定時間、メモ）を作成したい。
* **スポット・位置情報の紐付け**
  * 各スケジュール項目に、目的地（観光地、飲食店、宿など）の名前や住所、URL、メモ（「〇〇を食べる」「事前予約要」など）を記録できるようにしたい。
* **旅行中の実績チェック・ログ更新**
  * 実際に訪れたスポットに「訪問済」チェックをつけたり、実際の到達時間を記録できるようにしたい。
* **旅行の振り返り・フォト＆メモログ**
  * 旅行後に、スケジュールごとに写真やコメントを残して「旅行の思い出ページ」として保存・共有できるようにしたい。

### 2. 利用規模・環境など

* **対象ユーザー数:** 旅程を作成・共有するメンバー（数人程度／複数グループ運用も想定）
* **アクセス環境:** PC（事前準備・スケジュール組み用）およびスマートフォン（旅行当日の確認・更新用）

### 3. このテーマで学べる設計のポイント

* **時系列データ（日付 × 時間軸）**を扱う階層的データ構造（旅行 ＞ 日程 ＞ スポット/アクティビティ）の設計
* **複数ユーザー間での共有・編集権限（作成者、閲覧者、編集者）**のアクセス制御
* **予定（Plan）と実績（Actual）**の比較・保持のデータモデリング

### 4. 基本設計での検討事項・タスク

* [ ] **画面一覧・画面遷移のイメージ**
  * 旅行一覧画面、旅程編集（タイムライン）画面、スポット詳細・メモ画面、思い出ギャラリー画面など
* [ ] **データ（テーブル）の定義**
  * 旅行マスタ、旅行メンバー、日別スケジュール、スポット明細、振り返りログ・画像テーブルなど
* [ ] **仕様に関するヒアリング（疑問点の洗い出し・確認）**
  * メンバーの同時編集時の仕様、立替費用の精算機能（割り勘計算）を旅程に含めるかどうかなど
